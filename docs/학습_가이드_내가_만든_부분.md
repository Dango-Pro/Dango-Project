## 1. 학습 알고리즘 (SRS)

### 1-1. 전체 흐름

```
[사용자] → FlashCard에서 FAIL/HARD/GOOD/EASY 클릭
    → StudyPage.handleReview() → api.post("/study/review", { cardId, rating })
    → StudyController.reviewCard() → StudyService.processReview()
    → StudyLog 저장 (이력) + UserCardProgress 갱신 (상태) + applyAlgorithm()
```

### 1-2. 핵심 엔티티: UserCardProgress

**파일:** `backend/src/main/java/com/jpcard/domain/study/UserCardProgress.java`

| 필드 | 타입 | 설명 |
|------|------|------|
| **status** | StudyStatus | NEW → LEARNING → REVIEW → SUSPENDED |
| **nextReview** | LocalDateTime | 다음 복습 예정 시각 |
| **intervalMinutes** | int | 현재 간격(분). 1440 = 1일 |
| **ease** | double | SM-2 난이도 계수. 기본 2.5 |
| **repetitions** | int | 연속 정답 횟수 |
| **learningStep** | int | 학습 단계 인덱스 (0=1분, 1=10분 등) |
| **lapses** | int | FAIL 횟수. 8회 이상 시 SUSPENDED |

**중요:** `@UniqueConstraint(columnNames = {"user_id", "card_id"})`로 한 사용자당 한 카드에 대해 하나의 진행 상태만 갖도록 했습니다.

### 1-3. StudyService.applyAlgorithm() 상세

**파일:** `backend/src/main/java/com/jpcard/service/StudyService.java` (라인 347~333)

#### FAIL (다시)

```
status = LEARNING
learningStep = 0
intervalMinutes = learningSteps[0]  (예: 1분)
ease = max(1.3, ease - 0.2)
repetitions = 0
nextReview = now + intervalMinutes
```

#### HARD (어려움)

- **REVIEW 상태일 때:** `interval × 1.2`, `ease - 0.15`
- **LEARNING 상태일 때:** 현재 step의 interval 유지 (같은 단계 반복)

#### GOOD (좋음)

- **NEW/LEARNING:**  
  - step이 마지막이 아니면 → 다음 step으로 이동  
  - 마지막이면 → REVIEW로 승급, interval = 1일(1440분)
- **REVIEW:** `interval × ease` (최소 1일), **Fuzzing** 적용 (2일 이상 시 0~5% 랜덤 증가)

#### EASY (쉬움)

- **NEW/LEARNING:** 즉시 REVIEW, interval = 4일
- **REVIEW:** `interval × ease × 1.3`, **Fuzzing** 적용, `ease + 0.15`

### 1-4. 덱별 learningSteps

**Deck 엔티티:** `learningSteps = "1,10"` (기본값)

- 1분 → 10분 두 단계 학습
- `parseLearningSteps()`로 `int[] { 1, 10 }`로 파싱
- GOOD을 누르면 step 0 → step 1 → 승급

### 1-5. dailyLimit / reviewLimit

- **dailyLimit:** 오늘 신규로 학습한 카드 수 제한 (default 20)
- **reviewLimit:** 오늘 복습한 카드 수 제한 (default 200)

**getDueCards() 흐름:**

1. `countNewCardsStudiedToday()` → `firstStudiedAt`이 오늘인 카드 수
2. `countReviewsToday()` → `study_logs`에서 오늘 rating 수
3. `remainingNewLimit`, `remainingReviews` 계산
4. 남은 한도만큼만 `findNewCards` / `findDueCardsWithLimit` 호출

### 1-6. Timezone 처리

- User의 `timezone` 필드 (예: "Asia/Seoul")
- `ZoneId.of(userZone)`로 사용자 기준 "오늘" 시작/끝 시각 계산
- `LocalDateTime`으로 DB에 저장된 `LocalDateTime`과 비교

### 1-7. Leech (SUSPENDED)

- FAIL 시 `lapses++`
- `lapses >= 8`이면 `status = SUSPENDED`로 변경 → 해당 카드는 더 이상 복습 큐에 안 나옴

### 1-8. Sibling Burying

- 같은 `noteId`를 가진 카드들(형제 카드)이 있을 때
- 한 카드를 학습하면, 같은 note의 다른 카드 중 오늘 due인 것은 `nextReview`를 내일로 미룸

### 1-9. Interval Preview (미리보기)

- `previewIntervals()`: DB에 저장하지 않고 `simulateInterval()`로 각 rating별 다음 간격 계산
- `applyAlgorithmNoFuzz` 사용 (Fuzzing 제외, 결정적 결과)
- 프론트에서 "다시 (1분)", "좋음 (1일)" 형태로 버튼 라벨에 표시

### 1-10. 동시성 처리

- `processReview()`를 `TransactionTemplate`으로 감싸고, `DataIntegrityViolationException`이나 `ObjectOptimisticLockingFailureException` 시 최대 3번 재시도

## 2. 학습 패턴 분석

### 2-1. StudyLog 엔티티

- **user_id, card_id, rating, studiedAt** 저장
- `user_card_progress`는 "현재 상태", `study_logs`는 "이력"

### 2-2. StatsService

**파일:** `backend/src/main/java/com/jpcard/service/StatsService.java`

#### getDashboardStats()

- `totalCards`: 사용자가 소유한 덱의 총 카드 수
- `memorizedCards`: status가 REVIEW인 카드 수
- `dueCards`: `nextReview <= now`인 카드 수

#### getActivityData()

- `StudyLogRepository.countByDate()`: 날짜별 학습 로그 수
- 히트맵용 `{ date, count }` 리스트 반환

#### getExtendedStats()

- **오늘:** `countTodayReviews`, `countTodayCorrect` → 정답률
- **Streak:** `calculateStreak()` (아래 참고)
- **덱별 진행률:** NEW, LEARNING, REVIEW, SUSPENDED 카드 수
- **주간 트렌드:** 최근 7일 일별 학습량

### 2-3. Streak 계산

```java
// 오늘 학습 안 했으면 어제부터 역순으로
if (!studyDates.contains(today)) check = yesterday;
while (studyDates.contains(check)) {
    streak++;
    check = check.minusDays(1);
}
```

### 2-4. StudyLogRepository JPQL

- `countByDate`: `GROUP BY CAST(studiedAt AS LocalDate)`로 날짜별 COUNT
- `countTodayCorrect`: `rating IN ('GOOD', 'EASY')`인 로그만 COUNT
- `countByDateSince`: 특정 기간 이후 날짜별 집계

## 3. 커뮤니티 기능

### 3-1. PostService.search()

- `Sort.by(desc("isNotice"), desc("id"))` → 공지 상단 고정
- `searchWithAuthor(keyword, category, authorId, pageable)` → JPQL 검색

### 3-2. 첨부파일 저장 (saveAttachments)

- `MultipartFile` → `UUID + 확장자`로 `storeFilename` 생성
- `uploads/` 디렉터리에 저장
- `PostAttachment` 엔티티: `originalFilename`, `storeFilename`, `post_id`

### 3-3. PostController

- `@PostMapping(consumes = MULTIPART_FORM_DATA_VALUE)`로 게시글 생성 시 파일 수신
- `@Transactional(readOnly = true)` 상세 조회 → 첨부파일 lazy loading 시 세션 유지

### 3-4. PostDetailPage - 첨부파일 표시

- `post.attachmentUrls` (예: `["/uploads/uuid.jpg"]`)
- 이미지: `img` 태그 + 썸네일
- 일반 파일: `a` 태그로 다운로드 링크

### 3-5. PostCreatePage - 작성 후 해당 글로 이동

- `postService.createPost()` → `res.data.id` 반환
- `navigate(\`/posts/${createdId}\`)`로 상세 페이지로 이동

### 3-6. Comment - 대댓글

- `parent_id`로 부모 댓글 참조
- `renderComments(list, depth)` 재귀로 depth별 들여쓰기

## 4. 프론트엔드 연동

### 4-1. StudyPage

**파일:** `frontend/src/pages/StudyPage.tsx`

- `useSearchParams()`로 `deckId` 파라미터 읽기
- `fetchCards(studyMore)`: `GET /study/due?deckId=...&studyMore=...`
- `useEffect`로 현재 카드 변경 시 `GET /study/preview?cardId=...` 호출 → `intervalPreview` 갱신
- `handleReview(rating)`: `POST /study/review` → FAIL 시 `MAX_FAIL_RETRIES`(3) 이하일 때만 큐 뒤에 추가

### 4-2. FlashCard

**파일:** `frontend/src/components/FlashCard.tsx`

- `formatInterval(minutes)`: 분 → "1분", "12시간", "3일" 변환
- `intervalPreview`가 있으면 버튼 라벨에 `(1분)`, `(1일)` 등 표시
- `key={currentCard.id}`로 카드 변경 시 컴포넌트 리마운트 → 애니메이션 리셋

### 4-3. DashboardPage

- `Promise.all([/stats/dashboard, /stats/extended])`로 병렬 호출
- `memorizedPercent`, `streakDays`, `weeklyTrend`, `deckProgress` 표시

### 4-4. StudyHeatmap

- `GET /stats/activity` → `{ date, count }[]`
- `react-activity-calendar`의 `ActivityCalendar` 사용
- `getLevel(count)`: 0~10→1, 11~30→2, 31~60→3, 61+→4

### 4-5. postService

- `FormData`로 title, content, files 등 첨부
- `api.post("/posts", formData, { headers: { "Content-Type": "multipart/form-data" } })`

## 5. 학습 순서 추천

1. **UserCardProgress** 엔티티 읽기 → 각 필드가 알고리즘에서 어떻게 쓰이는지 이해
2. **StudyService.applyAlgorithm()** 한 줄씩 따라가며 FAIL/HARD/GOOD/EASY 분기 이해
3. **getDueCards()** 흐름 → timezone, dailyLimit, reviewLimit 적용 방식
4. **StatsService** → study_logs 기반 통계/Streak 계산
5. **StudyPage + FlashCard** → API 호출 → UI 표시 흐름
6. **PostService + PostDetailPage** → 첨부파일, 공지 상단 고정
