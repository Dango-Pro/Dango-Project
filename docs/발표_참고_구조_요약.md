# 발표 참고 - 덱·카드·게시판 구조 요약 (1페이지)

> 발표 전 빠르게 복습할 수 있는 구조 요약입니다.

---

## 1. 덱·카드 구조

```
User ──► Deck ──► CardTemplate (카드 양식)
           │
           └──► Card × N개
                    │
                    └──► UserCardProgress (사용자별 진행 상태)
```

| 엔티티 | 핵심 필드 | 설명 |
|--------|-----------|------|
| **Deck** | name, learningSteps, algorithmType | 덱마다 1분→10분, SM2/FSRS 등 설정 |
| **Card** | term, meaning, deck, noteId | 앞면/뒷면, noteId=형제 카드 묶음 |
| **UserCardProgress** | status, nextReview, ease | NEW→LEARNING→REVIEW, user+card당 1개 |

**학습 흐름:** 버튼 클릭 → `UserCardProgress` 갱신 + `StudyLog` 저장 → 알고리즘 적용

---

## 2. 게시판 구조

```
Post (게시글)
  ├── Comment (댓글) ── parent_id ──► Comment (대댓글)
  ├── PostAttachment (첨부파일) ── storeFilename: UUID
  └── PostLike (좋아요)
```

| 엔티티 | 핵심 필드 | 설명 |
|--------|-----------|------|
| **Post** | title, content, isNotice, category | 공지=isNotice, FREE/QNA/STUDY |
| **Comment** | content, post, parent | parent=null이면 최상위, 있으면 대댓글 |
| **PostAttachment** | originalFilename, storeFilename | UUID로 저장, 파일명 충돌 방지 |

**정렬:** `isNotice DESC, id DESC` → 공지 상단, 최신순

---

## 3. 발표 시 연결 포인트

| 발표 내용 | 연결되는 구조 |
|-----------|----------------|
| 학습 알고리즘 | Deck.algorithmType → UserCardProgress 갱신 |
| preview API | UserCardProgress 기반 simulateInterval |
| study_logs | StudyLog (card_id, rating, studiedAt) |
| 공지 상단 | Post.isNotice DESC |
| 첨부파일 | PostAttachment.storeFilename (UUID) |
| 대댓글 | Comment.parent_id |
